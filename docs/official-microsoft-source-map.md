# Official Microsoft Source Map

This is the initial evidence base for the toolkit. It links only to Microsoft documentation and distinguishes diagnostic collection from state-changing repair.

| Surface | Official Microsoft source | Collects / does | Reporting style | Safety boundary |
|---|---|---|---|---|
| WPR / WPA | https://learn.microsoft.com/en-us/windows-hardware/test/wpt | WPR creates ETW recordings with built-in or custom profiles; WPA analyzes them. | ETL timeline, searchable tables, pivotable graphs, Issues view. | Use a named, short reproduction window and local output path. Do not run unbounded or auto-upload ETL traces. |
| Performance Monitor | https://learn.microsoft.com/en-us/windows/win32/perfctrs/performance-counters-tools | PerfMon collects and views Windows performance-counter data; Data Collector Sets and Reports are available in its MMC. | Live charts and CSV/TSV/BLG logs. | State counter set, interval, duration, and retention. Counters are not intended for collection more than once per second. |
| Event Viewer | https://learn.microsoft.com/en-us/windows/win32/eventlog/event-logging | Centralized OS and application software/hardware events. | Channel records, filters, custom views, exported logs. | Read/export first. Do not clear logs, suppress providers, or claim an event is causal without corroboration. |
| Reliability Monitor | https://learn.microsoft.com/en-us/windows/win32/win7devguide/compatibility-and-reliability | Tracks stability index and correlates potentially destabilizing updates/installations with reliability history. | Date-oriented reliability trend/history. | Use for chronology, then corroborate with events and WER. Do not change software based on correlation alone. |
| WER | https://learn.microsoft.com/en-us/windows/win32/wer/about-wer | Crash, hang/no-response, and kernel-fault reporting with problem-report parameters and potential solutions. | Problem reports and reliability-history linkage. | Explain reporting and consent. Do not silently change WER/diagnostic-data policy. |
| WER local dumps | https://learn.microsoft.com/en-us/windows/win32/wer/collecting-user-mode-dumps | Optional locally stored user-mode dumps after a crash. | Minidump/custom/full dump files; default dump count is bounded. | Off by default and admin-configured. Do not globally enable full dumps; treat dumps as sensitive. |
| Process Monitor | https://learn.microsoft.com/en-us/sysinternals/downloads/procmon | Real-time file-system, Registry, process, and thread activity, including rich process metadata and stacks. | Filterable PML trace and process tree. | Apply filters and short duration first. Unfiltered capture can create very large logs and expose command lines/paths/user data. |
| Autoruns | https://learn.microsoft.com/en-us/sysinternals/downloads/autoruns | Inventories boot/login/autostart locations, services, tasks, drivers, extensions, and more. | Tabular UI; CLI CSV/XML output. | Inventory only by default. Never delete or disable entries automatically; get approval for any change. |
| Defender Performance Analyzer | https://learn.microsoft.com/en-us/defender-endpoint/tune-performance-defender-antivirus | Finds files, paths, processes, extensions, scan counts, durations, and scan reasons affecting Defender performance. | ETL recording and PowerShell report; exportable CSV/JSON. | Diagnose scan impact before considering tuning. Do not infer that an exclusion is safe or necessary. |
| Defender diagnostic bundle | https://learn.microsoft.com/en-us/defender-endpoint/collect-diagnostic-data | Creates a Defender support CAB containing traces, event data, update history, registry locations, and logs. | `MpSupportFiles.cab`. | Generate locally and disclose contents before transfer. Do not send support bundles to arbitrary destinations. |
| Defender command line | https://learn.microsoft.com/en-us/defender-endpoint/command-line-arguments-microsoft-defender-antivirus | MpCmdRun manages scans, security intelligence, and related diagnostic tasks. | Console output and command exit status. | Separate collection from scans/remediation. Do not disable protection or alter exclusions without explicit approval. |
| DISM | https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/repair-a-windows-image | Checks servicing-store health and can repair Windows images using configured or explicit sources. | Health result and servicing logs. | Inspect before repair; declare source and capture output. Do not invoke RestoreHealth silently or use untrusted sources. |
| SFC | https://support.microsoft.com/en-us/windows/experience/backup-recovery/use-the-system-file-checker-tool-to-repair-missing-or-corrupted-system-files | Checks protected system files and replaces corrupted cached copies. | Final result plus CBS.log details. | Do not interrupt scans or use manual protected-file replacement as routine remediation. |

## Design implications

1. Diagnostic tools should emit a manifest containing tool version, capture start/end, scope, filter/profile, destination, file hash, and consent state.
2. Captures must be local-only unless the operator explicitly chooses a transfer destination.
3. The user-facing report must separate observations, correlations, hypotheses, and approved actions.
4. Repair commands belong in an approval-gated phase and must record their exact command, source, exit code, and logs.
